# 1.4.4 · 壁纸过渡、缩略图与任务栏互斥

2026-11-05。用户已确认 1.4.3 在 Edge 实装通过，本轮处理随后反馈的两个 Web 问题和 Windows 任务栏重影。

## 壁纸过渡

原 skin.js 直接替换 background-image；既有 opacity 过渡不会让两张图产生淡入效果。

新增 wallpaper.js：先解码，再用 1.3s、cubic-bezier(.4,0,.2,1) 的动画覆盖旧图。快速选择只保留最新待切换目标，失败保留旧图。底部固定渐隐副本共享动画时轴，避免切换时上下不一致；透明图片也有与壁纸相同的基底色。同步模式读取桌面 wallpaperTransition，系统减少动态偏好优先。

这里同步的是效果与时长；网页获取桌面新图片仍经过本地通信和解码，因此不承诺跨两个进程同一帧开始。

## 缩略图与重复卡片

原设置页让 Gemini 页面中的 img 直接访问 http://127.0.0.1 图片地址，易受页面图片策略限制。改为扩展后台读取、生成最长 320×180 的预览，以 data URL 交给页面；旧引擎无法缩小时可退回原图。最多两路并发、16 个缓存项，文件 revision 变化失效。

设置面板有多个异步刷新入口；旧请求在新请求清空/填充列表后仍会继续追加，造成截图中的重复卡片。现在每轮渲染检查版本，旧结果不能继续追加或覆盖新结果。

## Windows 任务栏重影

用户当前配置为 prefer-web、hostWindowOnly=true、standaloneDesktopMode=true。排查发现：

- 原生 helper 的 kind=host 表示“宿主可用、存在可跟随的几何”，不等于“宿主正在前台”；旧互斥判断却将它当作前台豁免条件。
- 任务栏短暂接管后，网页立即报告 active=false，桌面可能重新显示；native helper 在壳层焦点变化时又可能重排窗口层级。
- 图片同步与焦点同步原本共用等待路径，慢取图还可能延后或合并掉焦点变化。

现将实际前台 foregroundKind 与宿主可用状态分开；识别宿主、浏览器、桌面、已知任务栏/系统壳层和其它应用。互斥策略独立到 companion-visibility.cjs：系统壳层临时接管且页面仍可见时保留 Web 归属；切换真实应用、IDE、其它浏览器页面、最小化/关闭或离线则释放。

网页分开发送 active/visible，可见页的短暂失焦延后 300ms，隐藏立即上报。焦点同步串行合并最新状态，图片下载独立进行且丢弃过期结果。原生壳层临时接管时不反复重排桌宠窗口。默认 both 模式和仅桌面模式未改为互斥。

原生程序已编译为源码哈希命名的 EXE，避免覆盖当前正在运行的程序。当前桌面进程未被中断；**桌面重启后才会加载新主进程逻辑和辅助程序**。安装器仍现场编译规范文件名，并排除开发缓存。本轮没有重新生成或验收桌面安装器。
