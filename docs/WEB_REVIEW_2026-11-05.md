# 两工程审阅与 Web 1.4.1 验证记录

日期：2026-11-05。审阅基线：桌面 `de30900`，Web `e7d6a33`。

## 1.4.2 · Edge 反馈后的按钮修正与咨询

用户反馈 Edge 实装卡顿已解决，但展开按钮左右渐变黑影复现，且形状从椭圆切成圆角矩形。此前对控件首帧规则的处理并不完整。

- 删除水晶药丸/圆按钮重绘，只适配原生按钮底色、文字色和边框色；不设尺寸、圆角、内外边距、字体、布局及动画。
- 复制/编辑规则不再通过泛用 icon-button 类命中未标注的展开控件；思考区内部清洗也排除按钮，避免再次重设其内边距。
- 控件内部左右渐变及伪元素光晕限定在 luminous 容器和按钮子树清除，消息正文和代码装饰不受影响。
- 回归测试新增原生几何逐帧比较、左右渐变/阴影检查、思考区文本按钮几何及焦点描边。用 1.4.1 构建运行新增断言会失败，新源码通过；这是具有代表性控件结构的隔离回归，不等同再次完成用户 Edge 实装确认。
- 本次只修改按钮样式、版本和相关测试/文档，未重构底部渐隐，未删除目录。

### 底部固定渐隐区

现有渐隐区的目标位置以 Composer/提示条为锚，视觉坐标本来是固定的；但实现仍在滚动事件后通过 16ms 定时器逐卡测量、写入局部 mask，并对变化量做 2px 去重，快速滚动时可能有追赶感。展开动画还会延后几何测量。

用户希望的静态区域应该让滚动内容自然经过固定的淡出区域，不在滚动热路径上重写每张卡的遮罩。这个方向可行，但应单独验证合成层方案：直接给滚动祖先挂整块 mask 已有 Firefox 毛玻璃采样失效记录；用单色渐变覆盖也无法在当前壁纸背景下得到正确的透明消失效果。下一步应以“固定空间位置、滚动不做逐卡写入、壁纸/blur/代码/输入框保持正确”为验收目标，而非仅移动现有渐变参数。此次没有把未经跨引擎验证的祖先 mask 混入按钮补丁。

### 目录整理

`git worktree list` 确认两个工程是同一 Git 仓库的两个工作区：桌面分支在 `D:\Catstella`，Web 分支在 `D:\Catstella-web`。不能把后者当成废弃仓库直接删除。后者的 `.git` 文件还指向前者的 worktree 管理目录。

真正冗余的是桌面工作区里的 `D:\Catstella\Gemini-Web-Companion` 旧副本。目前路径检测实测返回 `D:\Catstella-web\Gemini-Web-Companion`；安装器和角色素材同步工具没有读取这份旧内嵌副本。它可以作为后续单独清理变更移除，同时要更新旧交接文档中的构建路径、双副本漂移脚本及源码定位说明，并复查安装器和素材同步。

建议先清旧副本和错误文档，保留两个开发工作区；后续再整合分支/目录为统一代码树。Web 工作区里附带的旧桌面代码同样存在，但仍参与其根测试/CI，不能只删文件而不调整测试入口。发布当晚不宜把双端目录合并与视觉补丁混在同一变更中。

同一测试程序支持 `--baseline`（读取 `evidence/web-skin-before/` 源码备份）及 `--built`（读取 Chromium 构建内容）。前后报告为 `evidence/skin-baseline.json` / `skin-current.json`，截图为 `evidence/skin-browser.png`。

一次同机对照结果：计算样式读取 2720 → 0；累计样式重算约 63ms → 5ms；新版本没有禁用样式表帧、没有三个主要玻璃面失去模糊的采样。帧率/时间随机器与测试负载浮动，不应等同真实 Gemini 页面或 Firefox 的性能承诺。

浏览器断言覆盖：连续模糊、无样式表切换、局部工作量、快速重复切换、Enter 触发、编辑态与 Composer 分离、附件图片正常解码且不叠模糊、代码伪元素及内容渐变保留、关闭/重开皮肤、原宿主宽度还原、流式文本更新、气泡类名变化时的限定语义兜底。

3. **桌面主工程本次测试 63/66**：失败涉及固定端口 9651 的 EACCES、安装器 self-test 超时、Electron 目录 ACL 导致启动超时。源码未改动，不能把本次 Web 验证当作桌面安装器验收通过。
4. **Web 分支附带的旧桌面测试 39/40**：native heartbeat 超时与交接文档记录一致。此次没有改动旧桌面模块。
5. **仍存在长脚本和重复兼容封装**：tracker/widget/background 的职责偏集中，存储/消息兼容逻辑散布多处；额度 SSR 解析与隐式宿主结构仍是兼容风险。适合后续独立重构，今晚不混入皮肤补丁。
